# Архитектурный проект: Веб-приложение с аналитическим ML-сервисом

Учебный проект, реализующий многоуровневую архитектуру клиент-серверного приложения с интеграцией аналитического сервиса на Python для предиктивной аналитики, RFM-анализа и кластеризации клиентской базы.

---

## 🏗 Архитектура системы

Система разделена на 5 логических уровней (согласно схеме в `draw.io`):

1. **Клиентский уровень (Frontend):** 
   * **Стек:** Next.js, React, TypeScript, Tailwind CSS.
   * **Назначение:** Интерфейсы для пользователей, менеджеров и администраторов с дашбордами и графиками (React Hooks, Zustand, Recharts).
2. **Серверный уровень (Backend):** 
   * **Стек:** NestJS, TypeScript, REST API (JSON).
   * **Назначение:** Обработка бизнес-логики (Sales, Events, Tracking, Customers, Analytics), аутентификация и разграничение прав доступа (JWT + Guards + RBAC).
3. **Уровень данных (Database):** 
   * **Стек:** PostgreSQL / ClickHouse.
   * **Назначение:** Хранение сущностей (Users, Products, Orders, OrderItems, Events, Segments) через Prisma ORM.
4. **Аналитический / ML-сервис:** 
   * **Стек:** Python, FastAPI, scikit-learn, pandas, NumPy.
   * **Назначение:** Расчет RFM-метрик, кластеризация пользователей, прогнозирование оттока и анализ трендов продаж.
5. **Экспорт и отчеты:** 
   * **Стек:** S3-совместимое хранилище / CSV / Excel.
   * **Назначение:** Сохранение сгенерированных отчетов и выгрузок.

# Отчет по лабораторной работе

## Тема: Проектирование многоуровневой архитектуры программного обеспечения с интеграцией ML-модуля

### 1. Введение и цель работы
**Цель работы:** Спроектировать и описать архитектуру масштабируемого веб-приложения, включающего клиентский интерфейс, бэкенд на базе микросервисного/модульного подхода, реляционное хранилище данных и выделенный аналитический ML-контур.

### 2. Описание структурных уровней системы

Разработанная архитектура состоит из пяти взаимосвязанных уровней:

* **Клиентский уровень:** Построен на базе фреймворка **Next.js (React + TypeScript)**. Обеспечивает интерактивный интерфейс для трех ролей: Пользователь, Менеджер, Администратор. Для управления глобальным состоянием и отрисовки аналитических дашбордов используются *Zustand* и *Recharts*.
* **Серверный уровень:** Реализован на **NestJS** с использованием **TypeScript**. Отвечает за маршрутизацию (REST API / JSON), безопасность (JWT-токены, Guards, ролевая модель RBAC) и основную доменную логику (управление продажами, событиями, клиентами и трекингом).
* **Уровень данных:** Включает реляционную СУБД **PostgreSQL** (и аналитическую **ClickHouse** для больших объемов логов). Взаимодействие с базой данных на бэкенде стандартизовано с помощью **Prisma ORM**.
* **Аналитический / ML-сервис:** Представляет собой отдельный микросервис на **Python (FastAPI)**. Использует библиотеки **scikit-learn, pandas и NumPy** для выполнения расчетов: RFM-анализа, кластеризации клиентской базы, построения прогнозов оттока и анализа трендов продаж.
* **Экспорт и отчеты:** Отвечает за выгрузку и долгосрочное хранение результатов аналитики в S3-совместимые хранилища или файлы форматов CSV/Excel.

### 3. Описание сценариев взаимодействия (Use Cases / Data Flow)

1. **Авторизация и запросы:** Пользователь совершает действие в интерфейсе Next.js, отправляя защищенный HTTP-запрос. Сервер на NestJS перехватывает его, проверяет права доступа (RBAC) и выполняет бизнес-логику.
2. **Работа с транзакционными данными:** Сервер через Prisma ORM выполняет безопасные SQL-запросы к базе данных (PostgreSQL) для чтения или записи информации о пользователях, товарах и заказах.
3. **Аналитический пайплайн:** При запросе глубокой аналитики бэкенд отправляет HTTP/JSON-запрос к FastAPI-сервису. Python-модуль обрабатывает данные с помощью моделей машинного обучения и возвращает готовые метрики и сегменты клиентской базы обратно на сервер для отображения в дашборде.
